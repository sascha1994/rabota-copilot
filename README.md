# Rabota Copilot

Персональный помощник rabota.by: ежедневный поиск, оценка и подготовка пакетов отклика.
Режимы: автоматический и полуручной с просмотром, правкой и кнопкой отправки.
Добавлен браузерный отправитель `APPLICATION_SENDER=browser`. Без его настройки
пакеты остаются со статусом «Отправка не подключена».

## Ежедневная обработка и режимы

Новая основная логика: ежедневный поиск по текущему JSON-фильтру → оценка OpenAI →
отбор по порогу → выбор опубликованного резюме и подготовка письма → очередь → отправка.
По умолчанию: **09:00 по Минску, порог 75/100, лимит 10 подготовок и 10 попыток
отправки в день**, режим «Автоматический». Локальные лимиты OpenAI остаются общими
для всех функций и могут остановить подготовку раньше этого количества.

Кнопка **Режим и расписание** или `/automation` позволяет выбрать автоматический,
полуручной режим или паузу, изменить время ЧЧ:ММ, порог 0–100 и лимит 1–500.
Настройки хранятся в SQLite, действуют без перезапуска.

В автоматическом режиме подходящий пакет передаётся отправителю. Если оценка или
генерация вернула вопросы либо расхождения, пакет остаётся на проверке.
В полуручном режиме бот присылает вакансию, оценку, название выбранного резюме
и письмо со ссылками на портфолио. Кнопки позволяют отправить, отклонить
или изменить письмо. Правки сохраняются новой версией и отменяют прежнюю кнопку отправки.
Все пакеты доступны через **Очередь откликов** / `/queue`.
Переключение в авто не отправляет ранее подготовленные пакеты задним числом.

Поиск запускается один раз за местный день. Если бот включён после назначенного
времени, выполняется один догоняющий запуск за текущий день. Пропущенные дни не
восстанавливаются. Ошибка поиска фиксируется; повтор в тот же день автоматически
не выполняется. Web-источник сохраняет прежний предел страниц и ограничения доступа.
Работа выполняется только пока процесс бота запущен и ADMIN_ID настроен.

Очередь устойчива к перезапуску и повторному обнаружению вакансии: одна запись на ID
вакансии в этой базе. Отмеченные «Пропустить» и «Откликнулся вручную» исключаются.
Фильтры и подтверждённый профиль привязаны к заданию; изменение делает его устаревшим.
Есть явная кнопка повторной подготовки для ошибок и устаревших пакетов.
Состояние SENDING после сбоя превращается в UNKNOWN: повторная отправка запрещена
до ручной сверки. Успех допускается только при подтверждении отправителем.

### Подключение реальной отправки

В Telegram откройте «Очередь откликов» (`/queue`), выберите задание и проверьте
его категорию: «Проверить и отправить», «Ожидают обработки», «В работе»,
«Требуют внимания», «Отправлены», «Сняты с очереди» или «Все задания».
Категории показывают количество заданий и содержат страницы по 20 записей.
Из карточки можно вернуться в её категорию или открыть все категории.
«Требуют внимания» включает ошибки, остановленные и устаревшие пакеты и неизвестный
результат отправки. Остановленное, устаревшее или не подготовленное задание можно
отклонить. «Убрать из внимания» переносит задание с неизвестным результатом
в «Сняты с очереди» и сохраняет запрет повтора.
Если в разделе «Отклики» на rabota.by вы проверили, что отклика нет,
нажмите «Вернуть на доработку» и подтвердите «Проверил: отклика нет».
Бот создаст новую версию пакета в категории «Проверить и отправить».
Действие доступно также для снятых с очереди пакетов с неизвестным исходом.
Откройте нужное задание и проверьте
подготовленные тексты. Кнопка «Отправить» запускает браузерный отправитель;
бот сообщает о начале операции и присылает результат с обновлённой карточкой.
Подтверждённая доставка сохраняется вместе с версией пакета и временем.
Для SENT и UNKNOWN кнопки повторной отправки нет. Режимы «Полуручной»,
«Автоматический» и «Пауза» доступны в «Режим и расписание» (`/automation`).
После настройки браузерного отправителя в `.env` перезапустите процесс бота.

Локальные лимиты OpenAI считаются отдельно: `AI_DAILY_CALL_LIMIT` ограничивает
запросы, `AI_DAILY_TOKEN_LIMIT` — токены с резервами. Подходящая вакансия обычно
требует два запроса. При исчерпании локального лимита очередь ждёт до 03:00 по
Минску и продолжает автоматически, если бот запущен; это не ошибка подготовки.
Другие ошибки OpenAI автоматически не повторяются. Счётчики видны в `/automation`.

В `/automation` кнопки «Запросы OpenAI» и «Токены OpenAI» меняют общий локальный
бюджет без перезапуска: 1–1000 запросов и 10 000–10 000 000 токенов в сутки.
Настройки SQLite имеют приоритет над `.env` для всех операций оценки и генерации.
Уже начатые запросы не отменяются. Лимиты самого аккаунта OpenAI не изменяются.

### Вечерние предложения по профилю

В 23:00 по Минску бот присылает `/insights`: частые навыки и критерии из найденных
или обработанных за день вакансий. Время меняется в `/automation`. Бот должен
работать; после запуска сводка текущего дня доставляется, если время уже наступило.
Вакансия учитывается один раз для каждого пункта, даже при повторении слов и
повторной обработке. Показываются до шести навыков и четырёх критериев, встречающихся
минимум в двух вакансиях, с частотами и примерами ссылок. Источники — сохранённые
описания, заголовки и структурированные навыки; неполное покрытие описаний указано
в отчёте. Распознавание по словарю и ключевым навыкам площадки не требует OpenAI.

Профиль меняется только по кнопке пользователя: «Умею — добавить» подтверждает
навык, «Учитывать критерий» добавляет предпочтение для оценки, не жёсткий фильтр.
Частота упоминаний не подтверждает опыт кандидата и не означает обязательность
требования. Уже подтверждённые навыки отмечены. Повторное подтверждение не создаёт
дубликаты. Изменение профиля делает старые пакеты неактуальными по общим правилам.
Снимок отчёта сохраняется в SQLite; автоматическая доставка происходит один раз
в день, при сбое доставки его можно открыть командой `/insights`.

Установите `requirements-browser.lock`, выполните `browser-login` и укажите
`APPLICATION_SENDER=browser`. Задайте ID существующих резюме на сайте в
`RABOTA_RESUME_WEB`, `RABOTA_RESUME_WEB_UI`, `RABOTA_RESUME_GRAPHIC`, `RABOTA_RESUME_NARRATIVE`.
Пакеты прежнего AI-направления нужно подготовить заново перед отправкой.
Отправитель использует отдельный профиль в видимом Chrome. Бот открывает окно
при первом отклике, использует его для следующих и закрывает после 45 минут простоя.
Интервал можно изменить в `/automation` кнопкой «Простой браузера».
При ручной проверке окно остаётся открытым. Пройдите проверку в нём и нажмите
«Возобновить отправку» в Telegram. Бот проверит страницу и снимет паузу.
Пакет с неизвестным результатом по-прежнему нельзя отправить повторно.
Если окно закрыто, для ручной проверки откройте профиль командой `browser-login`
и закройте это отдельное окно перед возобновлением.

Бот выбирает опубликованное резюме по ID направления и отправляет персональное
сопроводительное письмо. Ссылки берутся из переменных `PORTFOLIO_GENERAL`,
`PORTFOLIO_AI`, `PORTFOLIO_GRAPHIC` и `PORTFOLIO_MARKETPLACE` в `.env`.
Для веб и UX/UI используется общее портфолио, для нарративного дизайна —
работы с нейросетями, для графики — графические работы. Для графических вакансий
с задачами маркетплейсов добавляется инфографика, а для вакансий с AI в названии —
портфолио с нейросетями. Ссылки добавляются локально в конец письма.
Ранее сохранённые копии «О себе» доступны в `data/site-resume-history`.

После проверки актуальности вакансии бот открывает форму, выбирает резюме
по точному ID, вводит письмо и нажимает кнопку отправки.
Перед последним нажатием повторно проверяются режим, версия, профиль и отметки.
Успех фиксируется только по видимому подтверждению сайта, вместе с ID резюме,
версией пакета, контрольной суммой письма и временем. Ошибка до последнего нажатия —
BLOCKED; ошибка после него — UNKNOWN без автоматического повтора.

CAPTCHA, неизвестная форма, необходимость входа и дополнительные согласия
останавливают отправку. `RABOTA_FOREIGN_CONSENT=1` допускается только после
явного согласия владельца на перечисленные площадкой страны: Россия, Казахстан,
Кыргызстан, Азербайджан, Грузия. Изменение списка стран требует ручной проверки.
Бот не меняет настройки видимости и не отвечает на дополнительные анкеты.
Предупреждение «Вы откликаетесь на вакансию в другой стране» проходит кнопкой
«Всё равно откликнуться» перед формой или после отправки. Перед продолжением
повторно проверяются режим и пакет. Это предупреждение не заменяет отдельного
согласия на передачу данных. Команда `browser-check` на таком баннере останавливается,
чтобы проверка формы не могла отправить отклик.
Сайт может изменить форму или ограничить автоматизацию; успешные модульные тесты
не заменяют проверку реальной формы.

Команда `send-job --job ID --revision ВЕРСИЯ` выполняет реальный отклик выбранного
пакета через те же проверки, что кнопка Telegram. Используйте её только после
просмотра пакета; перезапуск бота для этой разовой команды не нужен.

Проверка конкретного готового задания без сохранения резюме и без отправки:

```powershell
.\.venv\Scripts\python.exe -m app browser-check --job 3
```

При ошибке сохраняется локальный снимок `data/sender-check.png`; он может содержать
данные профиля. Его не следует публиковать. Браузерный профиль и история сайта не
входят в резервную копию SQLite. Docker-образ включает Chromium и виртуальный экран для входа через VNC.

## Браузерная сессия для интеграции

На Windows с установленным Google Chrome:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-browser.lock
.\.venv\Scripts\python.exe -m app browser-login
```

Откроется отдельный профиль `data/browser-profile`. Введите пароль/код самостоятельно
на сайте rabota.by. После входа закройте окно: профиль сохранится локально.
Можно выбрать `--channel msedge` или другой каталог `--profile-dir`.
Обычный профиль Chrome не читается и не копируется. Cookies и пароли не выводятся
в логи. Каталог сессии исключён из Git и контекста Docker через правила для data;
он содержит данные входа и не включён в SQLite-копии.
Команда создаёт сессию; затем проверьте форму командой browser-check.
Для Docker порядок входа приведён в разделе ниже.

## Резервное копирование и восстановление

При запуске бота создаётся проверенная копия существующей базы, затем копирование
повторяется каждые 6 часов. Если база ещё не создана, первая попытка ждёт следующего
интервала. Настройки: `BACKUP_INTERVAL_HOURS=6` (1–168; 0 отключает),
`BACKUP_DIR=data/backups`. `/status` показывает последний результат текущего процесса.
Ошибка копирования не останавливает поиск. Копии автоматически не удаляются:
следите за свободным местом и переносите нужные копии на отдельный носитель.

Используется SQLite Backup API, включая данные из WAL, затем `integrity_check`
и проверка базовых таблиц приложения. Копируется вся база: вакансии, профиль,
резюме, письма, история и учёт AI. Настройки `.env` и JSON-фильтры в копию не входят;
их сохраняйте отдельно. Копии содержат персональные сведения, как и исходная база.

Ручное копирование допускается во время работы бота:

```powershell
.\.venv\Scripts\python.exe -m app backup
.\.venv\Scripts\python.exe -m app backup-verify --input data/backups/ИМЯ_КОПИИ.sqlite3
```

Восстановление всегда создаёт **новый файл** и отказывается перезаписывать существующий:

```powershell
.\.venv\Scripts\python.exe -m app restore --input data/backups/ИМЯ_КОПИИ.sqlite3 --output data/restored.sqlite3
```

Для переключения остановите бота, восстановите копию, задайте
`SQLITE_PATH=data/restored.sqlite3` в `.env` и запустите бота заново.
Исходная база остаётся на месте. Восстановленная база возвращает и прежний локальный
учёт токенов: он может отставать от фактического расхода OpenAI после даты копии.
Проверка SQLite подтверждает целостность файла, но не полноту или достоверность сведений.

CLI удерживает системную блокировку на время работы бота с выбранным абсолютным
путём базы. Второй бот на том же пути получает понятную ошибку; после аварийного
выхода блокировка освобождается ОС. Файл `.bot.lock` удалять не требуется.
Блокировка не защищает от запуска одного Telegram-токена с разными базами или
на разных компьютерах. Не запускайте отдельный сборщик или импорт одновременно с ботом.

## Docker и обновление через Dockhand

Git Stack собирает образ из этого репозитория. Бот, Chromium и рабочий стол используют
один контейнер. Каталог данных находится на Docker VM и сохраняется при пересоздании
контейнера. Для проверки сайта через VNC используется тот же экран, на котором работает бот.

### Первый запуск на Docker VM

1. Создайте каталоги на VM:

   ```sh
   sudo install -d -m 0750 /srv/rabota-copilot
   sudo install -d -o 10001 -g 10001 -m 0700 /srv/rabota-copilot/data
   ```

2. При переносе дождитесь окончания отправки и остановите прежний экземпляр.
   На прежней машине выполните команду виртуального окружения `python -m app backup`.
   Скопируйте созданную проверенную копию в **новый** каталог как
   `/srv/rabota-copilot/data/vacancies.sqlite3`. Поместите действующие фильтры
   в `data/search.json`, а рабочий файл настроек — в `/srv/rabota-copilot/.env`.
   При установке с нуля используйте `.env.example` и `search.example.json`.
   Дайте UID 10001 чтение файла настроек и запись в перенесённые данные:

   ```sh
   sudo chown root:10001 /srv/rabota-copilot/.env
   sudo chmod 0640 /srv/rabota-copilot/.env
   sudo chown -R 10001:10001 /srv/rabota-copilot/data
   ```

3. Проверьте `TG_BOT_TOKEN`, `ADMIN_ID` и настройки OpenAI. Адрес прокси должен быть
   доступен из контейнера. Для отправки укажите `APPLICATION_SENDER=browser` и
   `RABOTA_RESUME_*` с ID опубликованных резюме. Compose задаёт канал Chromium и
   путь `/app/data/browser-profile`. Для первого входа удобно включить «Паузу»
   на прежнем боте перед резервной копией, затем выбрать полуручной режим после проверки.
4. В Dockhand добавьте репозиторий в **Settings → Git**, предоставив доступ на чтение.
   Создайте **Git Stack** в окружении этой VM. Выберите ветку `main`, файл `compose.yaml`
   и корень репозитория как контекст. Включите **Build images on deploy**, оставьте
   расписание синхронизации и вебхук выключенными. Нажмите **Deploy**.
   Проверка после запуска — Telegram-команды `/status` и `/queue`.
   [Руководство Dockhand](https://dockhand.pro/manual/#git-integration)

### Вход на rabota.by и ручная проверка

1. В терминале контейнера **bot** в Dockhand запустите `browser-view`. При первом
   запуске задайте отдельный пароль VNC и подтвердите сохранение. Он хранится
   в `/app/data/vnc.passwd`. Оставьте терминал открытым до окончания проверки.
2. На своём компьютере откройте SSH-туннель (подставьте имя пользователя и адрес VM):

   ```sh
   ssh -N -L 15900:127.0.0.1:5900 user@docker-vm
   ```

   В VNC-клиенте выберите хост `127.0.0.1` и TCP-порт `15900`
   (для TigerVNC — `127.0.0.1::15900`). Compose публикует VNC только на loopback VM.
3. Во втором терминале контейнера выполните `python -m app browser-login`.
   Войдите в аккаунт в окне Chromium через VNC и закройте окно браузера.
   Профиль сохраняется между обновлениями. Для будущей проверки, когда бот
   уже открыл окно, достаточно запустить `browser-view` и подключиться к нему.
   После отключения VNC-клиента просмотр завершается.
4. Для готового пакета проверьте форму командой `python -m app browser-check --job ID`,
   заменив ID на номер задания. Освободите браузерный профиль перед проверкой.
   Команда проверяет форму без отправки заявки. Верните нужный режим в `/automation`.

### Обновление

Отправьте изменения в `main`, дождитесь завершения текущей отправки и нажмите
**Deploy** у Git Stack. В журнале проверьте успешную сборку и запуск, в Telegram —
`/status` и содержимое очереди. Ручную копию перед обновлением можно создать
из терминала контейнера командой `python -m app backup`. Для возврата к прежнему коду
используйте `git revert` и повторный Deploy. При изменении формата базы понадобится
совместимая копия. Копии SQLite не содержат конфигурацию и авторизацию браузера.

Compose также запускается из корня репозитория командой `docker compose up -d --build`.
Чтобы выбрать другое место хранения, задайте переменную **Compose**
`RABOTA_STATE_DIR` с абсолютным каталогом Docker-хоста, где находятся `.env` и `data/`.
Файл приложения по пути `/app/.env` доступен контейнеру только для чтения.

Chromium запускается от UID 10001 с включённой песочницей. Для этого в репозитории
лежит профиль seccomp на базе [профиля Playwright](https://github.com/microsoft/playwright/blob/main/utils/docker/seccomp_profile.json).
В нём разрешён системный вызов `chroot` для запуска песочницы Chromium в её собственном
пространстве имён. У сервиса остаётся `cap_drop: ALL`.
На Linux-ядре VM должны быть доступны непривилегированные пространства имён пользователей.

## Запуск Telegram

Требуется Python 3.11+. Локальное окружение проекта уже подготовлено.
Для установки на другом компьютере:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
```

В `.env` заполнить `TG_BOT_TOKEN` из BotFather и `ADMIN_ID` (числовой ID владельца).
Если файла нет, скопировать `.env.example`. Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m app bot
```

Для получения ID можно сначала оставить ADMIN_ID пустым, запустить бота и
отправить `/id` в личном чате. Затем записать ID и перезапустить. До этого поиск
и данные недоступны всем; автоматического назначения владельца нет.
При регистрации предлагаемое название — **Работа BY · Помощник**,
username — `rabota_by_copilot_bot` (если свободен).

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка и кнопки |
| `/search` | Проверить новые вакансии и добавить подходящие в очередь |
| `/queue` | Очередь откликов. Ручной поиск и поиск по расписанию добавляют подходящие вакансии один раз. |
| `/clear` | Очистить список текущих фильтров с подтверждением |
| `/automation` | Режимы, время, порог и дневной лимит |
| `/tracked`, `/tracked 2` | Отмеченные вакансии, по пять на странице |
| `/history ID` | Последние сохранённые снимки описания вакансии |
| `/resumes` | Три направления резюме, версии, утверждение и экспорт TXT |

Бот работает только в личном чате владельца. Поиск выполняется в фоне,
повторный запуск блокируется. Публичный поиск запускается не чаще раза в минуту
в одном процессе бота. Изменение .env требует перезапуска. JSON-фильтры перечитываются
при новом запросе; текущий сбор использует снимок настроек на момент старта.
Для одного токена нужен один процесс long polling без активного webhook.

## Оценка вакансии через OpenAI

### Отдельный прокси OpenAI

В `.env` добавлена настройка `OPENAI_PROXY_URL`. Примеры (выберите свой адрес):

```dotenv
OPENAI_PROXY_URL=http://127.0.0.1:8080
# Или HTTP-прокси с авторизацией:
# OPENAI_PROXY_URL=http://user:password@proxy.example:8080
# Или SOCKS5:
# OPENAI_PROXY_URL=socks5://127.0.0.1:1080
```

Поддерживаются http, https, socks5 и socks5h. Спецсимволы в логине и пароле
нужно percent-encode отдельно, а не кодировать весь URL. Для большинства
HTTP CONNECT-прокси используется схема http://, даже при запросах HTTPS.
Пустое значение означает прямое соединение. Системные HTTP_PROXY/HTTPS_PROXY
для запросов OpenAI не используются: trust_env=False. Telegram, загрузка
вакансий и описаний используют прежние транспорты.

После изменения перезапустите бота. TLS-проверка остаётся включённой; HTTP
перенаправления не выполняются. При отказе прокси нет автоматического прямого
повтора. Сообщения ошибок не содержат URL с паролем. Региональные ограничения
и условия доступности провайдера остаются применимыми.
Адрес прокси нужно указать самостоятельно; локальный прокси-сервер не создаётся.
Зависимость httpx[socks] установлена и включена в requirements.lock.

При `unsupported_country_region_territory` OpenAI отклоняет доступ по стране или
региону. В этой среде такой ответ воспроизведён и на GET /models, без генерации
и передачи профиля. Смена модели сама по себе не исправляет региональный отказ.
Проверьте соответствие аккаунта и среды запуска условиям доступности OpenAI.
Бот теперь выводит эту причину отдельно от ошибок ключа, квоты и прав модели.
Для явных HTTP 400/401/403/404/422 снимается резерв токенов текущей попытки,
но сама попытка остаётся в дневном счётчике; старые неопределённые резервы
автоматически не меняются. Приложение не меняет сетевые настройки.

Под каждой новой карточкой есть **Оценить вакансию**. Бот получает полное описание
с публичной страницы rabota.by и передаёт его вместе с подтверждёнными
профессиональными фактами в OpenAI. Имя, пути файлов и цитаты PDF не передаются;
URL, email и телефонные номера в значениях фактов маскируются. Текст описания
вакансии также передаётся внешнему провайдеру. Все данные рассматриваются как
недоверенный текст, инструментов отправки откликов у модели нет.

В .env уже добавлены настройки:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
AI_DAILY_CALL_LIMIT=20
AI_DAILY_TOKEN_LIMIT=200000
```

Вставьте ключ нужного проекта и перезапустите бота. Используется официальный
Responses REST API, store=False и Structured Outputs с проверкой Pydantic.
По умолчанию gpt-5.4-mini; разрешены также gpt-5-mini и gpt-4.1-mini.
Переключение на более дорогую модель автоматически не выполняется.

Лимиты локальные, на сутки UTC, общие для этой базы: максимум 20 попыток и
200000 токенов по умолчанию. Перед вызовом резервируется консервативная оценка
по размеру запроса и запасу; после ответа она заменяется фактическим total_tokens.
При неизвестном исходе резерв остаётся. Автоповторов нет. Учёт других приложений
и проектов OpenAI недоступен; эти ограничения **не гарантируют отсутствие оплаты**.
Льготная квота с предоставленного пользователем скриншота зависит от настроек
аккаунта, допустимых моделей и общего расхода. Приложение не включает передачу
данных для улучшения моделей и не меняет настройки аккаунта. store=False не
означает отсутствия хранения или отключения настроенной в аккаунте передачи данных.

Ответ содержит оценку 0–100, рекомендацию направления web/web_ui/graphic/narrative/none,
объяснение, совпадения с ID подтверждённых фактов, расхождения и вопросы.
Отсутствующие в профиле навыки считаются неизвестными. Зарплата 3000 BYN на руки
трактуется как пожелание. Балл не является вероятностью найма и требует проверки.
Рекомендуется направление черновика, а не опубликованное резюме rabota.by.

В SQLite сохраняются результат, модель, время, usage/резервы и ключ кэша:
описание + заголовок/зарплата + подтверждённые факты с версиями + модель + промпт
и схема. Повторная оценка неизменённых данных не вызывает OpenAI, но описание
сайта читается заново для проверки актуальности. Изменение профиля во время
анализа отклоняет полученный результат. Очистка списка во время оценки запрещена;
готовые оценки остаются в кэше после очистки списка, чтобы не оплачивать их повторно.

Одновременно выполняется один анализ. CAPTCHA, HTTP-ошибка или неизвестная
разметка сайта останавливают получение описания. Неполный ответ, отказ модели,
некорректная схема или неизвестный ID факта не сохраняются как валидная оценка.
Обновление статуса архивирования и проверка подлинности всех текстовых выводов
модели пока не реализованы. Импорт новых PDF через Telegram остаётся отдельным следующим этапом.
Генерация писем доступна для утверждённых локальных резюме под вакансию.

## Отметки и история описаний

Под карточкой вакансии доступны **Интересно**, **Пропустить**,
**Откликнулся вручную** и **Снять отметку**. Это локальные решения владельца;
отметка ручного отклика не подтверждается площадкой и не запускает отправку.
Одновременно у вакансии одна текущая отметка, переходы сохраняются в истории.
Повторное нажатие той же отметки не создаёт повторное событие.
Отметки общие для всех наборов поисковых фильтров и сохраняются после очистки
списка и перезапуска. Они не скрывают вакансии из обычной выдачи автоматически.

Кнопка **Мои отметки** или `/tracked` открывает отдельный список с пагинацией:
`/tracked 2`. В нём сохраняются и карточки, удалённые очисткой текущего поиска.
Для повторного анализа такой карточки сначала верните вакансию в поиск.

При оценке вакансии, подготовке резюме или письма приложение сохраняет полученное
полное описание с хешем и временем в UTC. Неизменный текст обновляет время проверки,
изменённый создаёт новый снимок. Возврат к прежнему тексту после изменения тоже
создаёт новый снимок. Ошибка загрузки не заменяет старое описание пустым текстом.
Загрузка с сайта продолжается и при наличии кэша OpenAI, чтобы обнаружить изменения.

**История описания** или `/history ID` показывает до 10 последних снимков;
каждый можно скачать в TXT. После анализа отображается использованный снимок.
Резюме и письма сохраняют его ID, включая версии после ручной правки.
Для старых документов, созданных до этого обновления, снимок неизвестен.
История остаётся в базе после очистки поисковых списков. Снимки показывают ранее
полученный текст, а не текущий статус архивирования вакансии.

## Резюме в Telegram

Команда `/resumes` или кнопка **Мои резюме** открывает три направления:
веб/UI, графический и AI-дизайн. Первый базовый черновик создаётся локально из
подтверждённых профессиональных фактов; это заготовка с общими фактами профиля,
а не готовая адаптация и не копия опубликованного резюме rabota.by.

Под карточкой вакансии нажмите **Подготовить резюме** и выберите направление.
Описание вакансии и подтверждённые профессиональные факты передаются в OpenAI.
Используются те же модель, прокси, кэш и общий дневной лимит, что для оценки.
Одновременно выполняется одна оценка или генерация. Повтор одинаковой генерации
может взять ответ из кэша, но создаёт отдельную локальную версию для проверки.

Черновик показывается целиком, вопросы отображаются отдельно. Доступны:
**Исправить текст**, **Утвердить эту версию**, **Выгрузить TXT**,
**Показать изменения** и переход к предыдущей версии.
Редактирование сохраняет новую версию без изменения прежней и без утверждения.
Утвердить можно только последнюю версию направления при неизменном профиле.
При изменении подтверждённых фактов прежняя версия помечается устаревшей.
Исторические версии доступны для выгрузки с отметкой их статуса.

Версии, снимок фактов, связи с вакансией, модель и ссылки блоков на факты
хранятся в SQLite. Проверка схемы и ID фактов не доказывает достоверность
каждой формулировки: перед утверждением нужно прочитать весь текст.
Ручные правки проверяет пользователь. Утверждение относится только к версии
в приложении; переноса текста на сайт и отправки отклика нет.
TXT отправляется только в личный чат владельца, без контактов из профиля
в автоматически собранном тексте. Вручную введённые сведения попадут в экспорт.

## Сопроводительные письма

После подготовки резюме под вакансию и утверждения его версии появляется кнопка
**Сопроводительное письмо**. Откройте её и нажмите **Подготовить письмо**:
OpenAI получит описание вакансии, подтверждённые профессиональные факты,
направление и идентификатор выбранной локальной версии резюме. Полный текст
резюме (включая ручные правки) не передаётся; утверждения письма строятся по
подтверждённому профилю. Перед утверждением сверьте письмо с текстом резюме.

Письмо ограничено 1800 символами, вопросы показаны отдельно. Можно исправить
текст, утвердить конкретную версию, перейти к предыдущей версии и выгрузить TXT.
Правка и повторная генерация создают новый черновик; прежняя версия сохраняется.
Письмо связано с конкретным резюме и вакансией. Если профиль изменился или появилась
новая версия резюме, создание и утверждение письма для старой версии блокируются.
Экспорт исторического письма остаётся доступен с отметкой об устаревшем резюме.

Письма используют общий лимит попыток и токенов, кэш, модель и прокси OpenAI.
Неизвестные ID фактов не проходят проверку ответа. Ручные правки проверяет владелец.
Утверждение письма не отправляет отклик и не подтверждает обновление резюме на сайте.

## Профиль кандидата

Кнопка **Профиль** или `/profile` показывает количество подтверждённых,
неподтверждённых, спорных и исключённых пунктов. **Проверить факты** открывает
карточки с источниками (документ, страница и фрагменты текста).

- **Подтвердить** — разрешить использование конкретной версии факта.
- **Исправить** — ввести актуальную формулировку (до 1800 символов). После правки
  требуется отдельное подтверждение. Исходные источники сохраняются, добавляется
  уточнение пользователя.
- **Исключить** — убрать факт из разрешённых для использования без удаления истории.
- **Назад / Далее** — перейти между карточками. `/cancel` отменяет ввод исправления.

Пункты с вопросом требуют исправления перед подтверждением. Кнопка от старой
версии не может подтвердить новый текст. Доступ есть только у ADMIN_ID в личном
чате. Подтверждения, исправления и история сохраняются в SQLite и переживают
перезапуск. Очистка вакансий профиль не затрагивает. Пожелания профиля не меняют
поисковые фильтры автоматически.

В текущем рабочем окружении подготовлен и импортирован черновик из 30 пунктов по
предоставленным резюме. Персональный файл `data/candidate_profile.draft.json`
находится вне Git; он содержит источники и контрольные суммы исходных PDF.
Импорт начального черновика на другом компьютере:

```powershell
.\.venv\Scripts\python.exe -m app profile-import --input data/candidate_profile.draft.json
```

Импорт идемпотентен по ID: существующие пункты не перезаписываются, статусы
подтверждения из входного файла не принимаются. Новые пункты всегда требуют
проверки. Извлечение PDF внутри бота и загрузка новых резюме через Telegram пока
не реализованы. При переносе приложения отдельно перенесите БД или персональный
черновик, не публикуя их в репозитории.

Профиль хранится локально. Для анализа OpenAI используется интерфейс
`ProfileStore.confirmed()` возвращает только явно подтверждённые пункты для
будущего анализа вакансий. Наличие сведений в резюме не равно проверке их
актуальности пользователем.

## Изменение фильтров в Telegram

Кнопка **Очистить вакансии** или `/clear` запрашивает подтверждение очистки
списка текущего набора фильтров. Другие поиски и настройки сохраняются.
Сообщения, уже отправленные в Telegram, не удаляются. Следующий поиск может
снова добавить эти вакансии. Во время сбора очистка заблокирована; подтверждение
устаревает через 10 минут или при изменении фильтров. `/cancel` отменяет запрос.

Нажмите **Фильтры** → выберите параметр → отправьте новое значение сообщением.
Доступны запрос, регион, опыт, зарплата, валюта, стоп-слова, исключённые компании
и формат работы. Неверные значения не сохраняются, ввод можно отменить через `/cancel`.
Для региона можно ввести «Беларусь», «Минск» или числовые ID через запятую.
Регион необязателен: кнопка **Любой регион** или сообщение «нет» снимают
ограничение. В JSON это `"areas": []`; параметр area не передаётся источнику.
Для очистки зарплаты и исключений введите «нет».

В **Формат работы** доступны флажки: **На месте работодателя**, **Удалённо**,
**Гибрид**, **Разъездной**. Можно выбрать несколько форматов (подходит любой из них).
Нажмите **Сохранить**, чтобы применить выбор; кнопка **Любой формат** снимает все
флажки, после чего также нужно нажать **Сохранить**. До сохранения изменения
существуют только как черновик. Перезапуск или отмена сбрасывают незавершённый ввод.

Фильтры сохраняются атомарно в выбранном SEARCH_CONFIG JSON-файле и переживают
перезапуск. Изменения действуют для следующего поиска; текущий сбор использует
снимок фильтров на момент запуска. По завершении бот показывает количество добавленных
вакансий и кнопку перехода в очередь. Повторный поиск сохраняет состояние существующих заданий.

## Поисковые фильтры

Можно скопировать `search.example.json` в `search.json` и указать
`SEARCH_CONFIG=search.json` в .env.

| Поле JSON | Значение |
| --- | --- |
| `text` | Поисковая строка, по умолчанию Python |
| `areas` | Массив ID регионов, по умолчанию `["16"]` — Беларусь |
| `work_formats` | Массив ON_SITE, REMOTE, HYBRID, FIELD_WORK; пустой массив — любой формат |
| `experience` | null, noExperience, between1And3, between3And6, moreThan6 |
| `salary` | Зарплатный фильтр сайта, целое число или null |
| `currency` | Код валюты сайта, по умолчанию BYR |
| `excluded_title_words` | Подстроки названий для исключения, без учёта регистра |
| `excluded_employer_ids` | Массив строк с ID исключаемых работодателей |

Зарплатный фильтр передаётся сайту; это не локальная гарантия нижней границы зарплаты.

## Консольные команды

```powershell
.\.venv\Scripts\python.exe -m app collect --days 1
.\.venv\Scripts\python.exe -m app collect --days 7
.\.venv\Scripts\python.exe -m app list --limit 20
.\.venv\Scripts\python.exe -m app export --output data/vacancies.json
```

Глобальные `--config` и `--db` указываются перед командой. --days — от 1 до 30.
В web-режиме каждый запуск перечитывает выбранный период: исторического курсора
полноты нет, --full не меняет поведение. Периодический --watch для web отключён.

## Как работает источник web

Приложение читает HTML публичного `/search/vacancy` и извлекает данные карточек
из встроенного в страницу блока HH-Lux-InitialState. Внутренние API, браузерная
маскировка и обход CAPTCHA не используются. При 403, 429, проверке доступа или
неизвестной разметке сбор останавливается с сообщением, а не объявляет выдачу пустой.

Проверка 14 ноября 2026: реальный поиск Python по Беларуси за сутки вернул
14 вакансий за один запрос; данные сохранены в локальную базу. Это подтверждение
работы на момент проверки, а не гарантия постоянной доступности источника.

robots.txt площадки ограничивает обход URL с параметрами; наличие HTTP 200 не
означает разрешения на массовый сбор. Режим ограничен пользовательскими запросами
и небольшим числом страниц. При необходимости регулярного массового получения
данных требуется согласованный с площадкой источник.

При достижении лимита страниц выводится предупреждение о частичной выдаче.
Нет обещания полного охвата, восстановления пропущенного периода и проверки
архивирования. Порядок карточек на сайте может меняться. Изменение HTML потребует
обновления парсера. При сборе сохраняются карточки поиска; полные описания и их снимки
появляются при оценке и подготовке документов.

SQLite хранит ID, нормализованную карточку, даты обнаружения и причину исключения
по каждому набору фильтров. Повторные ID обновляются без создания дублей.
Частично полученные данные сохраняются при сбое. Время успешного web-сбора хранится
отдельно от курсора API и не означает полноту периода. Результаты list/export
включают накопленные вакансии текущего набора фильтров, а не только последний сбор.
Не запускайте несколько сборщиков на одной БД одновременно. PostgreSQL пока не реализован. Docker-конфигурация и резервное копирование
SQLite добавлены. История версий описаний
и подготовленных документов хранится в SQLite.

## Источник api

Сохранён как необязательный режим `VACANCY_SOURCE=api` для приложений с доступом HH.
В проверенной среде поиск без токена возвращал 403. Потребуются HH_USER_AGENT с
контактным email, HH_ACCESS_TOKEN и права приложения. Регистрация приложения
работодателя не является подходящим решением для персонального помощника соискателя.
Этот режим сохраняет пагинацию, разбиение окон и продолжение с курсора;
--watch доступен только ему. Автоматического получения OAuth-токена нет.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются доступ владельца, фоновый поиск, сообщения ошибок, пагинация,
фильтры, дедупликация, предел страниц, разбор HTML и сохранение после сбоев.
Тесты используют подставные ответы без сети; живой поиск проверялся отдельно.
